# Encuesta NL — Query Builder

Survey data query tool for the Nuevo León (CVNL) survey dataset.
DuckDB backend (FastAPI) + plain HTML/JS frontend.

## Running the app

```bash
# Backend (FastAPI) — defaults DB_PATH to ../data/encuesta_multianual.duckdb
cd backend
../.venv/bin/uvicorn main:app --port 8000 --reload

# Frontend (Vue + Vite dev server, proxies /api → :8000)
cd ../frontend
npm install   # first time
npm run dev   # http://localhost:3000
```

The API docs are at `http://localhost:8000/docs`.

## Database schema

Multi-year schema (see `db/schema.sql`). Every data table carries `wave_id`
(survey year, e.g. `'2025'`) as part of its primary key, so multiple survey
waves coexist without colliding. Waves `'2021'`–`'2025'` are currently loaded
(default = most recent = `'2025'`). Each wave is self-contained: question
numbering differs across years (e.g. "principal ocupación" is `p3` in 2024 and
`p1` in 2025), so cross-year comparison is Phase 2 (concepts/harmonization).

```sql
waves                 (wave_id PK, year, label, period, n_respondents, notes)
answers               (wave_id, respondent_id, question_id, option_id, value)          -- no PK; ordered physically
options               (wave_id, question_id, option_id) PK, option_label, concept_option_id
questions             (wave_id, q_id) PK, q_text, q_section, q_type, q_notes, q_info, q_block, concept_id
respondent_attributes (wave_id, respondent_id, attribute) PK, question_id, value
responses             (wave_id, respondent_id) PK, is_initial_respondent, nombre, factor_cvnl, city_id
```

- `respondent_attributes.attribute` is a friendly name (e.g. `sexo`);
  `.value` is the `option_id` in `options`, keyed by `.question_id` (e.g. `cp2`).
- `concepts (concept_id PK, label, q_type, comparable)` groups equivalent
  questions across waves (Phase 2 harmonization). `questions.concept_id` links
  each question to its concept. Populated by `db/build_db.py` from
  `db/concepts/*.csv` (generated by `db/concepts/build_concepts.py`). A question
  with a `concept_id` can be queried with `group_by="year"` to compare across the
  waves where it exists.
- `concept_options (concept_id, concept_option_id PK, label, sort_order)` is the
  canonical option catalog; `options.concept_option_id` maps each wave's option to
  a canonical one, so recoded options align across years (e.g. sexo 1/2 in 2022 ↔
  0/1 in 2023-25). `group_by="year"` groups categoricals by `concept_option_id`.
  Simple recodes (same option count) live in `db/concepts/concept_recodes_approved.csv`;
  option-SET changes (income brackets, etc.) are still Phase 2b.
- Queries pin `wave_id` (from `QueryRequest.wave_id`, defaulting to the most
  recent wave). `main.py` adds a `wave_id` predicate to every JOIN and WHERE.

## API endpoints

| Method | Path            | Description                        |
|--------|-----------------|------------------------------------|
| GET    | /api/questions  | All questions + options            |
| GET    | /api/attributes | Respondent filter attributes       |
| GET    | /api/cities     | Distinct city IDs                  |
| POST   | /api/query      | Run a query → JSON                 |
| POST   | /api/query/csv  | Run a query → CSV download         |
| GET    | /api/health     | Health check                       |

### POST /api/query body

```json
{
  "question_id": "p1",
  "filters": [{ "attribute": "sexo", "value": 1 }],
  "group_by": "answer",
  "wave_id": "2025"
}
```

`group_by` options: `"answer"` (flat), `"city_id"`, `"year"` (cross-year
comparison — only valid for questions with a `concept_id`), or any attribute name.
`wave_id` is optional; omit it to use the most recent wave.

## Key design decisions

- **Pivot mode** (`group_by != "answer"`): returns two tables — `counts` and `percentages` — both with a `Total` row/column.
- **City grouping** collapses raw `city_id` integers into 11 AMM municipalities + 4 aggregates (AMM, Periferia, Resto NL, Nuevo León) defined in `metadata.py`.
- **Sentinel values** `7777` / `8888` / `9999` (No aplica / No sabe / No contesta) are excluded from numeric stats but kept in counts/percentage tables.
- **`edad_anos`** is bucketed into age ranges via a SQL CASE expression rather than pivoting on individual integer years.
- Ordering of rows and columns follows `DESIRED_ORDERS` in `metadata.py` (canonical domain order for sexo, estudios, ingreso, etc.).
